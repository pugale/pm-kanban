PM-Kanban User Manual

PM-Kanban is a desktop application for managing projects and tasks from one data source, presented as a Kanban board, Gantt chart, calendar, agenda, table and dashboard.

Data is kept in JSON files stored in a SharePoint folder synchronized by OneDrive. The program needs no database, application registration or additional license. Teams and email notifications can be delivered by a Power Automate flow connected to the project data.

Global search: the field at the top filters every view by task code, title, description, owner, tag and email address.

1. First launch and setup

  1. In the team's SharePoint Document Library, create a dedicated folder, for example PM-Kanban.
  2. Select Sync or Add shortcut to OneDrive so that the folder appears in File Explorer.
  3. Open PM-Kanban and enter Settings using the ⚙️ button.
  4. Enter a valid business email address and, optionally, your name.
  5. Select Save.
  6. Select the synchronized SharePoint folder with Choose folder….

The email address identifies the project owner. The user who creates a project is its only editor; users opening it with a different email see it read-only. The configured email is automatically suggested as the owner of new tasks.

The Settings page can also run Check now, comparing tasks with the delivery registry written by Power Automate. The same check runs automatically every five minutes.

Local settings (email, name and folder) are saved on the PC, not in the project file.

2. Project management

The Project menu and adjacent selector let you switch projects and perform the main project operations.

New project

Requires a name and optionally accepts a customer, code prefix and tags. If the prefix is empty, one is suggested from the first word of the name. Each project is saved as a JSON file.

Open project

Open Project selects a JSON file even outside the configured folder. The file remains in its original location and subsequent edits are saved there during the session.

Save a copy

Creates an updated copy at a selected location. It does not replace the open file and does not change where subsequent edits are saved.

Delete project

Available only to the owner. After confirmation, it deletes the project file, its tasks and all associated attachments.

The selected project and last view are remembered on the PC. The app detects changes from OneDrive or other computers and refreshes the project list and data.

3. Creating and managing tasks

Select + New task or press Ctrl+N. Clicking a card, table row or other task item opens its details.

Field or commandBehavior
CodeOptional on creation. If blank, a unique code such as SARA-001 is generated from the project prefix.
Title, descriptionThe title is required; the description is free text.
StatusIn preparation, Ready to start, In progress, On hold, Completed or Cancelled.
PriorityLow, Medium, High or Critical.
Start and endRequired dates and times. The end cannot be earlier than the start. Changing the start preserves duration and notification lead time whenever possible.
OwnersAt least one valid email address. Multiple addresses can be separated by semicolons. All owners receive the notification.
ParticipantsOptional email addresses, separated by semicolons or lines. They also receive the notification.
TagsComma-separated labels, also included in global search.
ProgressFrom 0 to 100% in steps of 5 in the form. Completed tasks must be at 100%.
NotificationEnabled, disabled or already sent. Future tasks default to enabled, with delivery 15 minutes before the start. If the proposed time has passed, the app suggests the first suitable future time.
ChannelTeams, email or both. A configured Power Automate flow delivers the notification to owners and participants.
LinksURLs categorized as SharePoint, Teams, Jira, DevOps, Planner or Other. Links open in the default browser.
AttachmentsAfter the first save, multiple files can be added, opened and removed. They are copied beneath the app's data folder.
Duplicate and deleteDuplication creates a new task. Deletion removes attachments and Gantt dependencies after confirmation.

The bottom of the form displays creation time, last update and the user who made it. In read-only mode, fields remain visible but cannot be edited.

4. The six operational views

Kanban

  • One column for every status, including a task count.
  • Drag a card between columns to change its status.
  • Cards show code, priority, title, owners, dates, progress, participants and attachments.
  • Open tasks past their end time are marked with a flashing red outline.
  • The 🔔/🔕 button directly enables or disables notifications. A sent notification cannot be enabled again without changing its date or channel in task details.

Gantt

  • Displays all filtered tasks from Day to Year scale, with shaded weekends and a red "Today" line.
  • Drag a bar to move the task; drag its left or right edge to change the start or end.
  • Dragging snaps to one hour at Day scale and one day at the other scales.
  • Today centers the current-time line; zoom controls and the menu change the scale.
  • The Task column can be resized by dragging the right edge of its heading.
  • Link tasks creates FS (finish-to-start), SS (start-to-start), FF (finish-to-finish) or SF (start-to-finish) dependencies. Select the predecessor and then the successor. Esc cancels.
  • Arrows show the dependency type; clicking an arrow while editing and confirming removes it.
  • The predecessor is displayed as the parent and the successor as an indented child.
  • Export PNG saves the entire Gantt, not just the visible area, using the current zoom and column width. Oversized images are reduced.

Calendar

  • Month, week or day views, previous/next navigation and a return to Today.
  • Tasks appear on their start date. Any status can be included or excluded; only Ready to start is selected initially.
  • Saturdays, Sundays and Italian public holidays use a light-red background, and holiday names are shown.
  • Supported holidays: New Year's Day, Epiphany, Easter and Easter Monday, 25 April, 1 May, 2 June, 15 August, 4 October from 2026, All Saints' Day, Immaculate Conception, Christmas and St Stephen's Day.
  • Clicking a day creates, when permitted, a task starting at 9:00 with a default duration of one hour.

Agenda

Groups tasks by start date under Today, Tomorrow and later dates. It can filter all tasks, Ready to start, In progress or tasks assigned to the current user. Completed and cancelled tasks are hidden by default but can be shown. Overdue tasks are highlighted.

Table

Shows code, title, status, priority, owner, start, end and progress. Clicking a column heading sorts ascending or descending. Export to CSV saves the displayed, sorted tasks with a semicolon separator, UTF-8 encoding and protection against spreadsheet formula injection.

Dashboard

  • Metrics for total, open, completed, overdue, due today, due this week and average progress.
  • Charts by status, priority of open tasks, top ten owners by workload and completions over the last eight weeks.
  • Clickable lists for overdue tasks and tasks due today.
  • All values respect the global search filter.

5. Storage, synchronization and checks

Where data is stored

  • Each project is a JSON file in the synchronized SharePoint folder.
  • Attachments are stored in attachments/<projectId>/<taskId>/ (Italian folder name: allegati).
  • _notifiche-inviate.json is the delivery registry written by the Power Automate flow.
  • Copies created with Save a Copy can be opened and managed outside the default folder.

Save reliability

  • The project file is read from disk before every change to reduce the risk of overwriting another user's work.
  • Every task has a version number. A concurrent edit produces a conflict warning and reloads the latest data.
  • Saving uses a temporary file and rename operation, retrying when OneDrive temporarily locks the file.
  • File structure is validated on every read and before every save. Duplicate codes, invalid references, inconsistent dates and unexpected fields are reported.
  • Self-links, duplicate dependencies and dependency cycles are not allowed.
  • OneDrive conflict copies are reported above the work area.
  • Dates are stored as UTC and displayed in the PC's local time.
  • SharePoint version history can be used as an additional backup.
Read-only: edits, dragging, deletion and task links are disabled when the configured email does not match the project owner.

6. Common problems

Message or situationSolution
Folder unavailableCheck that OneDrive is running and the SharePoint folder is still synchronized, then select it again in Settings.
Project is read-onlyThe email in Settings must match the owner stored in the project.
Invalid structureThe file was edited manually or is damaged. Check the field reported by the error or restore an earlier version from SharePoint.
Conflict copyCompare the files listed in the warning. The app uses one copy; after choosing the correct data, delete the extra copies from the folder.
Notification state has not updatedCheck the Power Automate flow and use Check now. PM-Kanban does not send Teams messages or emails directly.
A second window does not openPM-Kanban allows only one instance at a time to prevent concurrent writes; the existing window is brought to the front.
The manual does not openUse the ? button again. If the manual files have been moved from the application folder, reinstall PM-Kanban.
